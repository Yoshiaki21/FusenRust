## D-001 gpui / gpui-component の固定方法（2026-11-23）

- gpui-component は現在、gpui を **git ではなく crates.io の `gpui-pre`（Zed の gpui のスナップショット）** から
  `=0.3.12` の厳密指定で使っている。gpui-component の git の rev を固定すれば gpui も自動的に一致する。
- そこで `Cargo.toml` では **`gpui-kit`（gpui + gpui-base + gpui-component + アイコン）を git の rev で固定**し、
  gpui は直接依存に書かない（`gpui_kit::*` から使う）。
  - gpui-kit rev: `48e53b11762a7ac37835acca889a924c569ff681`（2026-11-23）
  - これに対応する gpui: `gpui-pre =0.3.12`
- 理由: gpui-component が要求する gpui のバージョンを崩さないため。gpui を別に指定すると二重になり不整合の元になる。
- 更新するときは gpui-kit の rev だけを変え、専用のコミットに分ける。

## D-002 トレイは Linux では `ksni`、Windows では `tray-icon`（2026-11-23）

- `tray-icon` は Linux では GTK のメインループが必要で、gpui のイベントループと別スレッドで GTK を回す必要がある。
- KDE のトレイは StatusNotifierItem（D-Bus）なので、D-Bus だけで動く `ksni` を Linux で使う。
  メニュー操作は ksni のスレッドから `async-channel` で gpui 側に送る。
- Windows は Phase 5 で `tray-icon` を使う（Windows では GTK 不要）。

## D-003 付箋ウィンドウは方式 D（普通のウィンドウ ＋ KWin スクリプト）を採用（2026-11-23、ユーザー承認）

- 付箋 1 枚 = 枠なし・透明背景の普通のウィンドウ（xdg-toplevel）。layer-shell は使わない。
- 壁モード / 最前面モードは KWin スクリプト（D-Bus）で `keepBelow` / `keepAbove` を切り替える。
- 画面端へのドラッグによる最大化・タイル化は常駐の KWin スクリプトで取り消し、離した位置に置き直す。
- 理由: gpui では layer-shell の位置・層を後から変えられず（方式 A）、全面サーフェス方式（B）は白く表示された。
  方式 D は移動・最前面・編集・日本語入力・ドロップのすべてがユーザーの手動確認で動いた。
- 仕様 5.5 の「layer-shell のサーフェスとして作る」はこの方式に置き換える。

## D-004 版の仮番号・冪等性・添付の送信管理（2026-11-23、Phase 1）

- **仮番号は負の数**（-1, -2, ...）。サーバーの確定番号（正）と主キー (note_id, rev) がぶつからないため。
  未同期の版の上に重ねた版の `base_rev` は、確定したときに確定番号へ書き換える。
- **冪等性は `op_id`（UUIDv7）で取る**。仕様 6.3 の「note_id ＋ 端末の仮番号など」の具体化。
  `revisions` に `op_id TEXT NOT NULL UNIQUE` を追加し、送信の本文（`PushRevisionRequest`）にも含める。
  サーバーは同じ `op_id` の版には前回と同じ応答を返す。差分の取り込みで自分の `op_id` の版が来たら、仮番号の版を確定させる
  （送信の応答を受け取る前に落ちた場合に二重にならない）。
- **最新の版（head）**: 未送信の版があればその中で最後に作ったもの、なければ `server_seq` 最大の版。
- **`attachment_outbox` テーブルを追加**。同じ中身の blob を別の添付が共有すると、`blob_outbox`（sha256 単位）だけでは
  2 つ目の添付のメタデータ登録が漏れるため。
- **付箋の作成は `edit` 版**（仕様の kind に `create` がないため。`base_rev` は NULL）。
- **過去の版に戻す（revert）とき、ごみ箱の状態は今のまま**にする（本文・色・添付だけを戻す）。
- 同期の通信部分は `fusen_core::sync::Transport` トレイト（async fn）。実装は HTTP（Phase 4）や仮サーバー（テスト）。

## D-006 Phase 2（CachyOS 版デスクトップ）の実装上の判断（2026-11-23）

- **単一インスタンスと命令の受け渡しは D-Bus**。セッションバスの名前 `io.github.yoshiaki21.FusenRust` を
  「置き換えを許さない・順番待ちしない」で取得できたプロセスが 1 つ目。2 つ目は `Command` メソッドに引数を渡して終了する。
  （zbus の `Builder::name` は後から来たプロセスに名前を奪われる設定なので使わない）
- **引数なしで 2 回目に起動したら管理画面を開く**。`--manager` / `--quit` も追加した。
- **付箋の位置の保存**: Wayland ではアプリが自分の位置を知れないので、KWin の常駐スクリプトが
  移動・サイズ変更の終了時に `callDBus` でアプリの `WindowGeometry` を呼ぶ（位置は "x,y,幅,高さ" の文字列で渡す）。
- **位置の復元**: ウィンドウを開いた後、KWin から最初の位置の通知が来た時点（＝表示された）で保存済みの配置と層を適用する。
  KWin の初期配置が後から上書きすることがあるため、0.4 秒後と 1.2 秒後にもう一度適用する。
- **新しい付箋の位置**: KWin が決めた位置が他の付箋と重なれば 32px ずつ右下へずらす。
- **影の分の大きさ**: gpui-component の Root はクライアント側で描くウィンドウの周りに 20px の影を付ける。
  KWin の位置・サイズ（保存する値）は影の内側なので、ウィンドウは影の分（左右上下 20px）大きく開く。
- **「全付箋を一時的に前面に出す」はトグル**（もう一度実行すると元の層に戻す）。
- **管理画面の一覧から選んだ付箋**は一時的に常に背面を外して前面に出し、フォーカスが外れたら元の層に戻す。
- **編集の終了**: 編集欄のフォーカスが外れたとき、または付箋のウィンドウが非アクティブになったとき（他のウィンドウをクリック）。
- **終了時の保存**: 終了（トレイ・`--quit`・SIGTERM/SIGINT/SIGHUP）時に編集中の付箋を保存し、KWin の常駐スクリプトを解除する。
- **貼り付け**: 整形表示中は付箋をクリックしてから Ctrl+V で画像・ファイルを添付。編集中は画像・ファイルなら添付、文字は通常どおり貼り付け。
- **テーマは常に明るい色**（付箋が淡い色なので、システムが暗いテーマでも読みやすくするため）。
- **`--profile <名前>`**: 別の設定・データ・D-Bus 名・KWin スクリプトで動く。同じ PC で 2 つ動かして同期を試すため（Phase 4）。
- 保存場所: データ `~/.local/share/fusen-rust/`、設定 `~/.config/fusen-rust/settings.json`。
- 他の端末の名前の表示は Phase 4（それまでは端末 ID の先頭 8 文字）。

## D-007 この端末で新しく作った付箋は最前面で表示する（2026-11-23、ユーザー要望）

- 理由: 壁モードだと作った直後に他のウィンドウに埋もれて使いづらいため。
- 対象は「この端末で新しく作った付箋」だけ。他の端末から同期されてきた付箋（Phase 4）は壁モードで置く。
- 最前面の設定は配置（端末ごと）に保存され、再起動後も保たれる。ピンのボタンでいつでも壁に戻せる。

## D-008 付箋は位置が決まるまで透明にしておく（2026-11-23、ユーザー要望・案 A）

- 現象: 新しい付箋が、表示された直後にひとりでに少し動く。
- 原因: Wayland ではアプリが表示前に位置を決められない。KWin が置いた場所が他の付箋と重なると、
  アプリが表示後に 32px ずらす（D-006）。保存済みの位置への復元も表示後に行う。
- 対策: KWin の常駐スクリプトが、新しく開いた付箋ウィンドウを `opacity = 0` にしておく。
  アプリは動かす必要がなければすぐ、動かすなら置き直した後（0.4 秒後）に `opacity = 1` にする。
  KWin から位置の通知が来なかったときの保険として、開いてから 3 秒後には必ず見えるようにする。
- 制約: 1.2 秒後の置き直しで KWin の初期配置が上書きしていた場合は、そのときだけ動きが見えることがある。
- 起動時の復元（保存済みの位置へ動かす）も同じ仕組みで、動く様子が見えなくなる。

## D-009 Phase 3（同期サーバー）の実装上の判断（2026-11-23）

- **HTTP のステータス**:
  - 401: トークンなし・不正・無効化済み（`WWW-Authenticate: Bearer` を付ける）
  - 400: blob のハッシュが URL と違う、sha256 の形式が不正（`../` などでディレクトリをまたげない）
  - 413: アップロードが `FUSEN_MAX_UPLOAD_BYTES` を超える。Content-Length で先に判定し、ない場合は受け取りながら打ち切る
  - 422: 実体（blob）がない添付のメタデータ登録、メタデータ・実体がない添付を参照する版
  - 409: 同じ添付 ID を別の内容で登録、同じ op_id を別の付箋で使った
- **受付番号は全付箋で通し番号**（`MAX(server_seq) + 1`、書き込みは 1 つずつ）。
- **`/healthz` は `/healthz` と `/api/v1/healthz` の両方**で応答する（コンテナの死活確認とクライアントの両方から使うため）。
- **トークン**は `fsn_` + 32 バイトの乱数（16 進）。保存は SHA-256 だけ。`token revoke` は ID の先頭だけでも、1 つに決まれば受け付ける。
- **WebSocket** は認証付き（ヘッダーの Bearer）。30 秒ごとに ping を送る（リバースプロキシの無通信タイムアウト対策）。取りこぼしたら次の通知を待つ（端末は差分を取りに来るので、番号の欠けは問題ない）。
- **JSON の本文の上限は 16 MB**、blob は上限なしで受けて自分で判定する（axum の既定 2 MB を外す）。
- **コンテナ**: ビルドではワークスペースのメンバーを proto / core / server に絞り、デスクトップ（gpui）の依存を取得しない。
  実行は debian-slim、非 root（uid 10001）、`/data` をボリュームにする。
  podman は OCI 形式では HEALTHCHECK を無視する（Docker では有効）。
- **Quadlet（テスト用）はこの PC（127.0.0.1:9090）だけに公開**。開発 PC では 8080 を別のサーバー（llama）が使っているため（ユーザー確認）。
- **本番は Proxmox VE の fusen-server 専用 LXC の中の Docker**（ユーザー確認）。`deploy/compose.yaml` の待ち受けアドレス・ポート・データの場所・上限は
  `deploy/.env`（`.env.example` をコピー）で変える。既定は 127.0.0.1:8080（Caddy が同じ LXC）。Caddy が別ホストなら `FUSEN_BIND=0.0.0.0` にしてファイアウォールで絞る。
  データのディレクトリはコンテナのユーザー（uid 10001）が書き込めるようにしておく。LXC でビルドしない場合は `podman save | docker load` でイメージを運ぶ。
- テスト用の HTTP の Transport は `crates/fusen-server/tests/api.rs` に置いた。デスクトップ用は Phase 4 で作る。

## D-010 Phase 4（デスクトップの同期対応）の実装上の判断（2026-11-23）

- **同期は専用スレッドの tokio で動かす**。reqwest と WebSocket（tokio-tungstenite）が tokio を必要とし、gpui の実行器とは別のため。
  gpui とはチャンネルでやり取りする（gpui → 同期: 今すぐ同期・設定の変更・添付の取得・終了 / 同期 → gpui: 状態・他の端末からの変更・添付の取得完了）。
- **同期のきっかけ**: 接続時、WebSocket の `changed`、付箋の変更（`notes_changed` で即時）、20 秒ごとの未送信の確認（保険）。
  オフライン中に付箋を変更すると、待ち時間を待たずに再接続を試みる。
- **再接続の間隔**は 1 秒から倍々で最大 60 秒。
- **TLS は rustls（aws-lc-rs）**。サーバー証明書は OS の証明書ストアで確かめる（Caddy の内部 CA を OS に入れれば使える）。
- **添付の取得**: 本文中に表示する画像（PNG / JPEG / JXL）は同期のたびにすぐ取得。それ以外は開く・保存するときに取得する
  （開く・保存のための取得は、この端末の添付の上限に関係なく取得する）。
- **他の端末からの変更の反映**: 新しい付箋は左上付近（40,40 から 32px ずつずらす）に既定サイズ・壁モードで表示。
  ごみ箱に入れられたら閉じる。ごみ箱から戻されたら（デスクトップから外していなければ）表示する。
- **編集中に他の端末で更新された場合**（仕様 4.4）: 編集中の内容は上書きせず、付箋の上部に「他の端末で更新されました」を出す。
- **編集を始めた版は操作 ID（op_id）で覚える**。版の番号は同期で仮番号から確定番号に変わるため、番号で覚えると
  保存時に存在しない番号を `base_rev` として送り、誤って競合の印が付く。`NoteSnapshot::op_id` と `Store::rev_of_op` を追加した。
- **同期の状態の表示**: 管理画面の下部（接続済み / オフライン（理由）/ 未設定・未送信 n 件）とトレイのツールチップ。
- **端末名**は表示（管理画面の下部）にだけ使う。他の端末の名前は同期しない（版には端末 ID だけ。表示は ID の先頭 8 文字）。

## D-011 Phase 5（Windows 11 版）の実装上の判断（2026-11-24）

- **OS 依存は `platform/windows.rs` に置き、`platform/linux_kde.rs` と同じ関数を揃える**（`app.rs` などは共通のまま）。
  Win32 API は `windows-sys` 0.60 で呼ぶ。付箋ウィンドウの HWND は Linux と同じくタイトル（`fusen-note:<プロファイル>:<ID>`）で探す。
- **gpui の Windows 版の制約**:
  - `start_window_move` / `start_window_resize` が未実装。バーは `window_control_area(Drag)`（OS の `HTCAPTION`）にし、
    右下のつまみはサブクラスの `WM_NCHITTEST` で `HTBOTTOMRIGHT` を返す。バーの上のボタンは `occlude()` で移動の領域から外す。
  - gpui-component は Windows では影を付けない（`SHADOW_SIZE` = 0）ので `CSD_SHADOW` も 0。
  - gpui のマニフェスト（PerMonitorV2）は依存先の build.rs で作られ、こちらの実行ファイルには入らない。
    起動時に `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` を呼ぶ。
  - **gpui の更新処理（App を借用中）の中で ShowWindow / SetWindowPos を呼ぶと、gpui がその場で届いたメッセージを捨てる**
    （"RefCell already borrowed"）。付箋ウィンドウの操作はキューに積み、メインスレッドのメッセージ専用ウィンドウへの
    メッセージで後から実行する（`run_later`）。クローク（DWM の属性）だけはメッセージが出ないのでその場で行う。
- **壁モード**: `HWND_BOTTOM` に置き、サブクラスの `WM_WINDOWPOSCHANGING` で前に出ようとする z 順の変更を `HWND_BOTTOM` に書き換える。
  **最前面モード**: `HWND_TOPMOST`。管理画面から選んだときは一時的に書き換えをやめる（フォーカスが外れたらアプリが元に戻す）。
- **タスクバーに出さない**: `WS_EX_TOOLWINDOW`。gpui は表示した状態でウィンドウを返すので、一度隠して出し直す（クローク中なので見えない）。
  最大化はさせない（`WS_MAXIMIZEBOX` を外し、バーのダブルクリックと `SC_MAXIMIZE` を無視する）。
- **位置が決まるまで見せない（D-008）**: KWin の透明化の代わりに DWM のクローク（`DWMWA_CLOAK`）。
  開いた直後に `note_window_opened` が最初の位置をアプリに送り、KDE と同じ流れ（保存済みの配置を適用 → 見せる）に乗せる。
- **座標**: 位置は仮想スクリーンの物理ピクセル、大きさは論理ピクセル（`GetDpiForWindow` で割る）。値は DWM の拡張フレーム
  （見えている枠）で読み書きする。拡大率の違うモニターへは、位置だけ動かしてから（`WM_DPICHANGED` が起きる）大きさを決め直す。
  保存した位置にモニターがなければ主モニターの左上付近に置く。新しい付箋は画面の中央に開く（Wayland では位置は無視される）。
  位置の通知は移動・サイズ変更の終わり（`WM_EXITSIZEMOVE`）。
- **単一インスタンス**: 名前付きミューテックス `Local\FusenRust.<プロファイル>`。2 つ目のプロセスは隠しウィンドウ
  （クラス `FusenRust.Ipc.<プロファイル>`）を探して `WM_COPYDATA` で引数を渡す。`AllowSetForegroundWindow` で前面に出す権利を譲る。
- **トレイ**: D-002 のとおり `tray-icon`。隠しウィンドウと同じ専用スレッドで作り、メッセージループを回す。アイコンは仮（コードで描いた黄色い付箋）。
- **ログオフ・シャットダウン**: 隠しウィンドウ（メッセージ専用ではなくトップレベル）で `WM_ENDSESSION` を受け、終了の命令を送り、
  終了時の保存が終わるまで最大 5 秒待つ。
- **自動起動**: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の値（`FusenRust` / `FusenRust (<プロファイル>)`）。
- **ファイルを既定のアプリで開く**: gpui の `open_with_system`（Windows でも動く）のままで変更なし。
- **既定のフォント**は Windows では `Yu Gothic UI`（Noto Sans CJK JP は標準では入っていないため）。
- **配布**: まずは zip（`scripts/package-windows.ps1`。`fusen-desktop.exe` と README.txt だけ。インストール不要）。
  リリース版はコンソールを出さず（`windows_subsystem = "windows"`）、ログは `%LOCALAPPDATA%\fusen-rust\fusen-desktop.log` に追記する
  （命令を渡すだけの 2 つ目のプロセスが消さないよう追記。5 MB を超えたら起動時に `.old` へ）。起動できないときはメッセージボックスで知らせる。
- **データの場所**（`dirs`）: データ・設定とも `%APPDATA%\fusen-rust\`（`--profile X` は `profiles\X\`）。

## D-012 付箋を貼るかどうかは端末ごと（2026-11-24、ユーザー要望。spec.md 3.2 を変更）

- 全部の付箋を全部の PC に貼る必要はないため、**貼るかどうかを端末ごと**にする。付箋の内容・色・タイトル・添付・ごみ箱の状態は今までどおり全端末で共有する。
- 端末ごとの配置（`placements`。同期しない）で表す。**配置がない付箋 = この端末には貼っていない**。DB の変更はない。
- 他の端末で新しく作られた付箋は**自動では貼らない**（管理画面の一覧に出るだけ。新しい PC で初めて同期しても何も貼られない）。
  一覧のクリック・「貼る」ボタンで、この端末に貼る（そのとき配置ができる）。「外す」は配置の `visible` を落とす（今までの「デスクトップから外す」と同じ）。
- ごみ箱は全端末で共通のまま。他の端末でごみ箱から戻された付箋は、ごみ箱に入る前にこの端末に貼ってあった場合だけ貼り直す。
- 管理画面の一覧に「貼ってある」の印・貼る / 外すボタン・「この端末に貼ってある付箋だけ」の絞り込みを付けた。
- 本文中の画像を同期のたびに先に取得するのは、**この端末に貼ってある付箋の分だけ**（`Store::missing_blobs_of_pasted`）。
  貼ったときは、最初の位置の通知（配置の保存）の後に同期を走らせて取得する。

## D-013 付箋のタイトル（2026-11-24、ユーザー要望・案 A）

- **版にタイトルの項目（`title`）を足す**（同期され、履歴に残り、revert で戻る）。端末・サーバーの DB にマイグレーション v2（`revisions.title`）。
  本文とは別に持つ。タイトルの変更は色と同じく確定した時点で版を 1 つ作る（種類 `title`）。空にするとタイトルを外す。
  保存時に改行・制御文字は空白にし、前後の空白を除き、200 文字までにする。
- **互換**: 古い形式の JSON（`title` なし）は空のタイトルとして読む（`#[serde(default)]`）。版の種類に `#[serde(other)] Other` を足し、
  知らない種類（将来の版のアプリが作った版）を受け取っても同期が止まらないようにした。
- **一覧などに出す名前**は `fusen_core::markdown::display_title`: タイトル、なければ本文の最初の空でない行
  （見出し・リスト・引用・チェックボックスの記号、リンク・画像の書式を落とす）、どちらも空なら「（空の付箋）」。
  一覧・ごみ箱・履歴で使い、検索の対象にもタイトルを加えた。
- **バーの UI**: ピンのボタンの右（色のボタンとの間）に、太字・小さめの文字で 1 行表示し、はみ出したら省略する。
  タイトルの欄はバーの一部なのでドラッグで移動できる。**バーのダブルクリック**かメニューの「タイトルを編集…」で入力欄になり、
  Enter かフォーカスが外れたら確定、Esc で取り消し。
  - Windows: バーは OS の移動の領域（`HTCAPTION`）だが、gpui は `WM_NCLBUTTONDBLCLK` を click_count = 2 の押下として届ける。
    サブクラスで捨てるのをやめ、アプリが処理すれば既定の処理（最大化）は呼ばれない（`SC_MAXIMIZE` も引き続き止める）。
  - KDE: 押した瞬間に KWin の移動が始まるので、ダブルクリックがアプリに届くかは未確認。届かなくてもメニューから編集できる。
- **本文の編集中に同じ端末で色・タイトルを変えた場合の誤った競合の印をなくした**。`save_edit` は、編集を始めた版より後の版が
  すべてこの端末のものなら、最新の版を `base_rev` にする（他の端末の版が挟まっていれば今までどおり編集を始めた版のまま＝競合の印）。
- ウィンドウのタイトル（`fusen-note:<プロファイル>:<ID>`）は付箋を見分ける印なので、付箋のタイトルは入れない（画面に描くだけ）。

## D-014 付箋の完全削除は端末ごと。全端末で削除されたらサーバーからも消す（2026-11-25、ユーザー要望。spec.md 3.1・7 章を変更）

- **端末**: 管理画面のごみ箱に「完全に削除」「ごみ箱を空にする」（確認ダイアログあり）。`Store::purge` が版・添付のメタデータ・
  下書き・配置・outbox を消し、**どの添付からも参照されなくなった blob だけ**ファイルを消す。添付は別の付箋の版から参照されることがある
  （メタデータの `note_id` は最初に添付した付箋）ので、他の付箋の版が参照する添付は残す（`json_each` で版の attachments を調べる）。
- **ごみ箱にある付箋だけ**削除できる。サーバーと同期している端末では、**未送信の版がある間は削除しない**
  （ごみ箱へ移した版が届く前に消すと、他の端末ではごみ箱に入らないままになるため）。サーバー未設定ならローカルだけで消す。
- **墓標**（端末のマイグレーション v3 `purged_notes`。同期しない）: `reported`（票を送ったか）、`revived`（復元されて取り込み直した）、
  `max_seq`（削除した時点で持っていた版の最大の受付番号）。同期の最後に未送信の票を `POST /notes/{id}/purge` で送る。
- **サーバー**（マイグレーション v3 `purge_votes`・`purged_notes`）: ごみ箱にある付箋の票だけ記録する。
  **有効なトークン（無効にしておらず、一度でも使われたもの）全部の票がそろったら**版・添付のメタデータを消し、参照されなくなった
  blob のファイルを消して墓標を残す。応答は `waiting`（残りの端末数つき）/ `purged` / `not_deleted`。サーバーが知らない付箋は `purged`。
  - 新しい版が届いたら、その付箋の票を消して数え直す。墓標のある付箋への版は **410 Gone**。
  - `fusen-server token revoke` の後にも票がそろったかを判定し直す（使わなくなった PC のトークンを無効にすると、その PC 待ちだった付箋が消える）。
    無効にし忘れたトークンがあると、サーバーからは消えない。
- **他の端末で復元された場合**: 差分で、墓標のある付箋の `max_seq` より新しい版が届いたとき
  - ごみ箱にないままの版（復元）→ 取り込み直し（この端末には貼らない。D-012）、同期の後で `GET /notes/{id}/revisions` から全履歴と添付のメタデータを取り直す。
    そのため全版の API の応答を `NoteHistoryResponse`（版＋添付）に変えた（端末からは使っていなかった）。取り直しに失敗しても `revived` が残るので次の同期で再試行する。
  - ごみ箱にあるままの版（ごみ箱の中で色を変えたなど）→ 取り込まず、票を送り直す（サーバーは新しい版で票を消しているため）。
  - `max_seq` 以前の版（自分が送った版が差分で戻ってきたなど）は無視する。
- **410 を受けた端末**（同じトークンを 2 台で使っていたなど）は、その付箋を未送信の版ごと消す（票は送らない）。
- 同じ中身の blob が完全削除でちょうどサーバーから消えた場合に備え、添付のメタデータの登録に失敗したら blob がサーバーにあるかを確かめ、
  なければ未送信に戻す（次の同期で送り直す）。
- **注意（D-015 で修正）**: 最初の実装では受付番号を `MAX(server_seq) + 1` で採番していたため、受付番号の最大の版を完全削除すると
  配り済みの番号を使い回し、端末が他の端末の版を取りこぼした。
- **同時に検討したが未実装**（着手するときに D-016 / D-017 として決める）:
  - 設定と付箋の書き出し / 復元: zip 1 つ（manifest・SQLite の online backup で取った fusen.db・blobs・settings.json）。
    復元は「全部」か「設定と配置だけ（付箋はサーバーから）」。使用中の DB は差し替えられないので次の起動時に入れ替える。
  - サーバーのデータが消えた・古いとき: サーバーに `server_id` を持たせて入れ替わり・巻き戻りを検出し、端末の版を
    rev・op_id ごと送り直す API（追加のみ・op_id で冪等）で戻す。端末は op_id で突き合わせて rev・server_seq を付け直す。


## D-015 受付番号は使い回さない。サーバーが巻き戻っていたら端末は最初から取り直す（2026-11-25、不具合の修正）

- **不具合**: サーバーは受付番号を `MAX(server_seq) + 1` で採番していた。完全削除（D-014）で受付番号の最大の版を消すと最大値が下がり、
  配り済みの番号（実例: 12〜23）をもう一度使った。端末は取り込み済みの番号（22・23）より後しか取りにいかないので、
  その後の他の端末の版が届かなくなった（双方で「競合の印」が付き、同期していないように見えた）。
- **サーバー**: マイグレーション v4 で `meta.last_server_seq`（既存の最大値で初期化）を作り、これで採番する。版を消しても戻らない。
- **差分の応答に `max_server_seq`**（配った最大の受付番号。`#[serde(default)]` で古いサーバーは `None`）を足した。
- **端末**: `max_server_seq` が取り込み済みの番号より小さければ、警告を出して 0 から取り直す（1 回の同期で 1 度だけ）。
  既に持っている版は op_id で重複せず、完全削除した付箋の古い版は墓標の `max_seq` で無視される。
  今回ずれた端末（取り込み済み 22・23、サーバーの v4 の初期値 21）は、更新したアプリで同期すれば自動で取り直して揃う。
  サーバーをバックアップから戻したとき（巻き戻り）の取りこぼし防止にもなる（配った番号が端末より少ない場合だけ。同じか多ければ検出できない）。


## D-016 サーバーの管理画面（2026-11-25、ユーザー要望）

- **設定したときだけ起動する**: `FUSEN_ADMIN_LISTEN`（例 `0.0.0.0:9010`）を設定したときだけ、同期の API とは**別のポート**で待ち受ける。
  空・未設定なら起動しない。常には要らないので、使うときだけ設定（`deploy/.env` / Quadlet）を有効にして作り直す運用。
  ポートは 9010（テスト環境では 8081 が使用中のため。ユーザー指定）。
- **公開範囲**: compose・Quadlet ともホストの `127.0.0.1:9010` にだけ公開する（compose では `FUSEN_BIND` に関係なく）。
  Caddy では中継しない。別の PC からは SSH のポート転送（`ssh -L 9010:127.0.0.1:9010 <サーバー>`）。
- **認証**: `FUSEN_ADMIN_PASSWORD`（8 文字以上）のパスワード画面。未設定・短いときはサーバーが起動しない。
  ログイン後はランダムなセッション ID のクッキー（HttpOnly・SameSite=Strict、操作がなければ 8 時間で失効）。セッションはメモリだけ
  （再起動でログアウト）。失敗したら 1 秒待たせる。比較は SHA-256 をとってから定数時間で行う。
- **CSRF**: 変更の操作（POST）はすべて、セッションごとの確認用の値をフォームに埋めて確かめる。
  応答には `Cache-Control: no-store`・`X-Frame-Options: DENY`・CSP（外部の読み込みと他サイトへのフォーム送信を禁止）を付ける。
- **できること**: トークンの発行（発行直後の画面に 1 回だけ表示。URL には載せない。コピーのボタン）・無効化（確認あり。
  `token revoke` と同じく完全削除の判定をし直す＝`revoke_and_purge` を共通化）・端末名の変更・**無効のトークンだけ**一覧から削除
  （そのトークンの票も消す。版の `token_id` は記録として残す）。一覧には状態・発行・最終使用（「3 分前」と日時）・受け付けた版の数。
  ほかに完全削除の待ち状況（付箋ごとの削除済み / まだの端末）と使用量（付箋・ごみ箱・版・添付・実体の数と容量・完全削除の数・最後の受付番号）。
- **作り**: `crates/fusen-server/src/admin.rs`。サーバー側で HTML を組み立てる（テンプレートの依存は足さない）。JavaScript は確認とコピーだけ。

### 移動の問題と回避策（ユーザーと相談が必要）

gpui（`gpui-pre 0.3.12`）では、layer-shell サーフェスの **margin（位置）と層を作成後に変えられない**。

- **方式 A: 付箋 1 枚 = サーフェス 1 つ（仕様どおり）**
  - 移動はドラッグ終了時にサーフェスを作り直す。ドラッグ中は付箋が動かない（移動量だけ表示）。
  - 層の切り替えも作り直し。作り直しの瞬間にちらつく可能性がある。
- **方式 B: モニター × 層 ごとに全面の透明サーフェス（推奨）**
  - 付箋はサーフェス内の要素。`Window::set_input_region` で付箋の矩形だけ入力を受け、それ以外のクリックは下に抜ける。
  - ドラッグに滑らかに追従する。層の切り替えは Top 側のサーフェスへ移すだけ。
  - モニターをまたぐ移動は、ドラッグ終了時に移動先のモニターのサーフェスへ移す。
  - 注意: サーフェスの数は「モニター数 × 2」で固定。全面の透明サーフェスなので GPU メモリを少し多く使う。
- **方式 C: gpui をフォークして `set_margin` / `set_layer` を足す**
  - 変更自体は小さいが、gpui の更新のたびにフォークを追従する必要がある。

### ユーザーの手動確認の結果（2026-11-23）

- 方式 A: 最前面の切り替えと本文の編集はできた。ドラッグでの移動はうまくできない。
- 方式 B: 透明になるはずの全面サーフェスが**白く**表示され、最前面に出て、**画面全体を覆わない**。
  白い範囲の中では移動・編集はできた。→ gpui の layer-shell は四辺 anchor（コンポジターがサイズを決める）の扱いに問題がある模様。不採用候補。
- トレイの例（普通のウィンドウ）: KDE のウィンドウメニューに「常に最前面に表示」があり、使えることを確認。

### 方式 D: 普通のウィンドウ ＋ KWin スクリプト（推奨・`p0_kwin_window`）

- 付箋は普通のウィンドウ（xdg-toplevel、枠なし・透明背景）。
- Wayland にはアプリが自分のウィンドウを常に背面/最前面にするプロトコルがないので、
  **KWin スクリプトを D-Bus（`org.kde.KWin /Scripting` の `loadScript` → `run`）で実行**して設定する。
  - 壁モード = `keepBelow`、最前面モード = `keepAbove`
  - `skipTaskbar` / `skipPager` / `skipSwitcher` / `onAllDesktops` も設定する
  - ウィンドウはタイトル（`fusen-note:<id>`。枠なしなので画面に出ない）で見分ける
- 移動・サイズ変更は KWin の機能（`Window::start_window_move` / `start_window_resize`）を使う。
- 起動して KWin から読み出し、keepBelow・skipTaskbar・onAllDesktops が設定されたことを確認した。
- 位置の復元: Wayland ではアプリが自分の位置を指定できないが、KWin スクリプトで `frameGeometry` を設定できる。
  位置の保存は、KWin スクリプトから `callDBus` でアプリに知らせる方式を Phase 2 で検証する。
- KWin スクリプトは同じプラグイン名を使い回すため、呼び出しは 1 つずつ行う（同時に呼ぶと競合した）。
- 画面端へのドラッグで最大化・タイル化される問題（ユーザー報告）:
  アプリ起動中だけ常駐する KWin スクリプト（`fusen-guard`）で、付箋ウィンドウの `tileChanged` / `maximizedChanged` を受けて即座に戻す。
  KWin のウィンドウルール（maximizehoriz/maximizevert の強制）でも止められるが、ユーザー全体の KWin 設定（kwinrulesrc）を書き換えるので採用しない。
  スクリプトから左タイル化して、元の大きさのまま残ることを確認済み。
  取り消すと KWin はドラッグ前の位置に戻す（ユーザー報告）ので、`interactiveMoveResizeStepped` でドラッグ中の位置を覚え、
  取り消した直後にその位置（`clientArea(MaximizeArea)` の中に補正）へ置き直す。異常終了で残っても、次回起動時に入れ替わり、影響は付箋ウィンドウだけ。
- 注意: 「デスクトップを表示」（Meta+D）では隠れる（Windows 版と同じく許容の想定）。
