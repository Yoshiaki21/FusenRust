# FusenRust 作業フェーズ

フェーズの順に進めてください。各フェーズの完了条件を満たしたらユーザーに報告し、
「手動確認項目」の確認をお願いしてから次へ進みます。

---

## Phase 0: 技術検証（CachyOS）

**目的**: gpui の layer-shell まわりなど、OS の制約に関わる部分が実現できるかを最初に確かめる。
本実装には入らず、`crates/fusen-desktop/examples/` に小さな検証用プログラムを作る。

### 作業

1. Cargo ワークスペースを作り、gpui と gpui-component を git の rev に固定して追加する
   （gpui-component が要求する gpui のコミットに合わせる）
2. 検証用プログラムで次を確認する:
   - [ ] layer-shell の `Bottom` 層に、枠なし・透明背景・角丸の四角を表示できる
   - [ ] 左上 anchor ＋ margin で好きな位置に置ける。ドラッグで移動できる
   - [ ] `Bottom` ⇔ `Top` の切り替え（その場でできるか、作り直しが必要か）
   - [ ] 2台目のモニターに表示できる
   - [ ] gpui-component の TextView で Markdown（画像を含む）を表示できる
   - [ ] ダブルクリックで複数行入力に切り替え、フォーカスが外れたら表示に戻せる
   - [ ] **layer-shell のサーフェス上で fcitx5 の日本語入力ができる**
   - [ ] JXL 画像を `jxl-oxide` でデコードして表示できる
   - [ ] ファイルのドラッグ＆ドロップを受け取れる
   - [ ] `tray-icon` などでトレイアイコンを出せる（gpui のイベントループと共存できる）

### 完了条件

- 上の項目それぞれについて「できた / できない / 回避策」を `docs/decisions.md` にまとめる
- できない項目があれば、回避策の案を出してユーザーと相談する
  （例: 日本語入力ができない場合、編集だけ通常ウィンドウで行う、など）

### 手動確認項目（ユーザー）

- 付箋がアプリのウィンドウの下、アイコンの上に表示されるか
- 日本語入力ができるか
- 2台のモニターで表示が崩れないか

## Phase 1: fusen-proto / fusen-core

**目的**: データモデル・端末側の保存・履歴・添付を、UI なしで完成させる。

### 作業

- `fusen-proto`: API の型（版、添付メタデータ、差分の応答、WebSocket のメッセージ）
- `fusen-core`:
  - SQLite のスキーマとマイグレーション（`docs/spec.md` 3章）
  - 付箋の作成・版の保存（kind ごと）・ごみ箱・復元・過去の版に戻す
  - 下書きの保存と復元
  - 添付: SHA-256 の計算、blob の保存（同じ中身は1つ）、メタデータ、上限サイズの判定
  - 本文中の `attachment://` 参照の抽出
  - 同期エンジンの土台（outbox、仮番号から確定番号への置き換え）。通信部分はトレイトで差し替え可能にする

### 完了条件

- ユニットテスト: 版の追記のみ、ごみ箱と復元、revert、下書き、blob の重複排除、上限サイズ
- `cargo test --all` と clippy が通る

## Phase 2: CachyOS 版デスクトップ（ローカルのみ）

**目的**: 同期なしで、CachyOS 上で付箋アプリとして使える状態にする。

### 作業

- 付箋ウィンドウ（`docs/spec.md` 5.1、5.5）
  - 壁モード / 最前面モードの切り替えボタン（付箋ごと）
  - 移動・サイズ変更・色の変更
  - ダブルクリックで編集、フォーカスが外れたら保存
  - チェックボックスのクリック操作
- 添付（5.2）: ドロップ・貼り付け・選択、インライン画像（PNG/JPEG/JXL）、チップ、開く・保存・削除
- 管理画面（5.3）: 一覧・検索・ごみ箱・履歴（戻す）・設定（同期関連は Phase 4 で有効化）
- トレイ、単一インスタンス、`--new` / `--show-all`、自動起動（5.4）
- 配置の保存と、起動時の復元

### 完了条件

- 再起動しても付箋・配置・最前面の設定が復元される
- 編集中にアプリを強制終了しても、次の起動で下書きが復元される

### 手動確認項目（ユーザー）

- 付箋を貼る・動かす・大きさを変える・色を変える
- 最前面ボタンの動作
- Markdown の表示、画像（PNG/JPEG/JXL）の表示、その他のファイルの添付と開く・保存
- 履歴から前の版に戻せるか
- KDE のショートカット設定から `fusen-desktop --new` を呼べるか

## Phase 3: 同期サーバー

**目的**: サーバーを作り、CachyOS 上の podman で動かせるようにする。

### 作業

- `fusen-server`（`docs/spec.md` 6章）: API、WebSocket、トークン認証、トークン管理コマンド
- 後勝ちの判定（`server_seq`）、`base_rev` による競合の印、冪等な受け付け
- blob のストリーミング受信とハッシュ検証、上限サイズ
- `deploy/Containerfile`、`deploy/fusen-server.container`（Quadlet）、`deploy/compose.yaml`、`deploy/Caddyfile.example`

### 完了条件

- 結合テスト: 2つの仮想クライアントでの同期、オフライン中の編集の後送り、競合の印、
  不正なトークンの拒否、blob のハッシュ不一致の拒否
- CachyOS の podman でイメージをビルドして起動し、`/healthz` が応答する

### 手動確認項目（ユーザー）

- podman（Quadlet）で起動できるか
- トークンを発行できるか

---

## Phase 4: デスクトップの同期対応

**目的**: CachyOS 版をサーバーにつなぎ、リアルタイムに同期させる。

### 作業

- 設定画面でサーバーURL・トークン・端末名を登録
- 同期の流れ（6.4）: 起動時の差分取得、outbox の送信、WebSocket、再接続
- 他の端末からの新しい付箋の配置、編集中の更新の表示（4.4）
- 同期状態の表示（管理画面・トレイ）
- 添付の取得方針（画像はすぐ、その他は必要になったとき）

### 完了条件

- 同じPCで2つの設定（別々のデータディレクトリ）で起動し、互いに同期できる
- サーバーを止めて編集し、再開すると送られる

### 手動確認項目（ユーザー）

- 2台目のPC（またはもう1つの起動）で、編集が数秒以内に反映されるか
- 競合したときに履歴に両方の版が残るか

## Phase 5: Windows 11 版

**目的**: 同じコードで Windows 11 版を動かす。

### 作業

- `platform/windows.rs`（`docs/spec.md` 5.6）: HWND の取得、壁モード（最背面の維持）、最前面モード、
  タスクバーに出さない、高DPI対応
- トレイ・単一インスタンス・自動起動の Windows 対応
- ファイルを既定のアプリで開く処理の Windows 対応
- 配布形式の検討（まずは zip でよい）

### 完了条件

- CachyOS 版と同じ機能が Windows 11 で動き、CachyOS 版と同期できる

### 手動確認項目（ユーザー）

- 付箋が他のウィンドウの下に留まるか（クリックしても前に出てこないか）
- 最前面ボタンの動作
- 拡大率の違うモニター間での表示
- CachyOS との相互同期
